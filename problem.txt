# Bootstrap Loader Issue - Complete Analysis & Resolution

## Root Causes (Akar Masalah)

Ada 3 masalah utama yang menyebabkan bootstrap loader gagal:

### 1. Docker Desktop Port Forwarding Issue

- Problem: Anda menjalankan bootstrap loader dari Windows machine (bukan di dalam Docker), mencoba akses PostgreSQL di
localhost:5433
- Why it failed: Docker Desktop di Windows tidak mem-forward port 5433 ke container secara konsisten. Port forwarding hanya
bekerja untuk beberapa port tertentu.
- Root cause: Windows WSL/Docker Desktop architecture tidak sama dengan Linux - forwarding bisa rusak atau timeout

### 2. PostgreSQL Password Authentication Failed

- Problem: Container PostgreSQL sudah berjalan dengan konfigurasi lama (tanpa password atau password berbeda)
- Why it failed: Volume Docker persistent - ketika container down, data tetap ada. Saat restart, PostgreSQL tidak rebuild
dengan .env terbaru yang punya password WH721HDA
- Root cause: PostgreSQL init hanya terjadi pertama kali volume dibuat. Restart container tidak re-init user/password

### 3. Missing CREATE SCHEMA Statement

- Problem: SQL script hanya membuat tables, tidak membuat schema operational_raw terlebih dahulu
- Why it failed: PostgreSQL throw error: schema "operational_raw" does not exist
- Root cause: Template {{SCHEMA}} di-replace dengan operational_raw, tapi schema itu sendiri tidak ada

### 4. Data Type Mismatch - user_id Float vs Integer

- Problem: CSV file punya nilai user_id seperti 35092.0 (float), tapi schema define sebagai INTEGER
- Why it failed: PostgreSQL COPY reject float values untuk integer column
- Root cause: CSV data export ke format float, schema expect integer

--------

## Solutions Applied (Solusi Yang Diterapkan)

### File 1: docker-compose.yml ✏️

What changed:

- Added new service bootstrap-loader yang berjalan di dalam Docker network (bukan dari Windows)
- Service ini connect ke postgres_warehouse:5432 (internal) bukan localhost:5433 (external)
- Added env_file: .env untuk load environment variables

⎘
bootstrap-loader:
build:
context: .
dockerfile: docker/airflow/Dockerfile
image: project-airflow:latest
command: python -m scripts.loaders.bootstrap_loader
env_file: .env                    # ← Load .env file
environment:
POSTGRES_HOST: postgres_warehouse  # ← Use service name, not localhost
POSTGRES_PORT_warehouse: 5432      # ← Use internal port, not 5433
volumes:
- ./scripts:/opt/airflow/scripts
- ./sql:/opt/airflow/sql
- ./datasets:/opt/airflow/datasets
- ./logs:/opt/airflow/logs
networks:
- dataflow_network
depends_on:
postgres_warehouse:
condition: service_healthy


Why this fixes problem #1 & #2:

- Bootstrap loader now runs inside Docker network - bisa akses PostgreSQL langsung
- Tidak perlu port forwarding
- PostgreSQL dapat environment variables dengan benar

--------

### File 2: scripts/common/config.py ✏️

What changed:

- Updated default values untuk POSTGRES connection dict
- Changed host default dari localhost → postgres_warehouse
- Changed port default dari 5433 → 5432
- Added fallback values untuk DB name, user, password

⎘
# OLD
POSTGRES = {
"host": os.getenv("POSTGRES_HOST", "localhost"),          # ❌
"port": int(os.getenv("POSTGRES_PORT_warehouse", 5433)),  # ❌
"dbname": os.getenv("POSTGRES_DB_warehouse"),             # ❌ No fallback
"user": os.getenv("POSTGRES_USER_warehouse"),             # ❌ No fallback
"password": os.getenv("POSTGRES_PASSWORD_warehouse"),     # ❌ No fallback
}

# NEW
POSTGRES = {
"host": os.getenv("POSTGRES_HOST", "postgres_warehouse"),      # ✅
"port": int(os.getenv("POSTGRES_PORT_warehouse", 5432)),       # ✅
"dbname": os.getenv("POSTGRES_DB_warehouse", "Looker_ECommerce"),
"user": os.getenv("POSTGRES_USER_warehouse", "postgres_warehouse"),
"password": os.getenv("POSTGRES_PASSWORD_warehouse", "WH721HDA"),
}


Why this fixes problem #2:

- Fallback values memastikan konfigurasi valid bahkan jika .env tidak di-load
- Correct defaults untuk Docker environment

--------

### File 3: sql/02_operational.sql ✏️

What changed:

- Added CREATE SCHEMA IF NOT EXISTS {{SCHEMA}}; di awal script
- Changed users.id dari INTEGER → NUMERIC
- Changed orders.user_id dari INTEGER → NUMERIC
- Changed order_items.user_id dari INTEGER → NUMERIC
- Changed events.user_id dari INTEGER → NUMERIC

⎘
-- NEW: Create schema first
CREATE SCHEMA IF NOT EXISTS {{SCHEMA}};

-- OLD users.id
CREATE TABLE IF NOT EXISTS {{SCHEMA}}.users (
id INTEGER PRIMARY KEY,        -- ❌
...
)

-- NEW users.id
CREATE TABLE IF NOT EXISTS {{SCHEMA}}.users (
id NUMERIC PRIMARY KEY,        -- ✅
...
)

-- Similar changes for orders, order_items, events user_id columns


Why this fixes problem #3 & #4:

- Schema created before tables
- NUMERIC type accept both integers dan floats (e.g., 35092.0)
- Foreign key relationships tetap valid

## Option 1: Setup Port Forward Manual ✅ (Paling mudah)

Buka terminal baru dan jalankan:

⎘
docker run -it --rm -p 5433:5432 --network project_dataflow_simulation_dataflow_network postgres:18 psql -h
postgres_warehouse -U postgres_warehouse -d Looker_ECommerce


Atau gunakan socat untuk port forward:

⎘
docker run -it --rm -p 5433:5432 alpine/socat TCP-LISTEN:5433,fork TCP:postgres_warehouse:5432


Setelah itu, dari Windows terminal lain:

⎘
psql -h localhost -p 5433 -U postgres_warehouse -d Looker_ECommerce
